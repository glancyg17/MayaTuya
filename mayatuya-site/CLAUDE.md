# Maya Tuya — site repo (read this first)

Static bilingual (EN/ES) site for **Maya Tuya**, a travel-tech and cultural brand on the Tren Maya route in Mexico, founded by **Glancy**.
Plain HTML/CSS/JS generated by one Python script. No framework, no WordPress, no database.
Hosted on **Cloudflare Workers (static assets)**; deployed automatically from `main` by Workers Builds.

This file is a **public-safe subset of the private Master Codex** (v6.4). The Codex is the source of truth and is deliberately *not* in this repo.
If this file and a request from Glancy disagree about a price, capacity or rule, ask — don't guess.

## Repo layout (important)

The git repo root contains the **active project in the `mayatuya-site/` folder**. Run every command from inside `mayatuya-site/`.
The old files at the repo root (a previous `src/`, `docs/`, etc.) are **legacy and dead — do not edit them**. Removing them needs Glancy's OK (pending).
Workers Builds uses `mayatuya-site/` as its root directory; if a build ever can't find `wrangler.jsonc`, check that setting in the Worker's build settings first.

Glancy works on **Windows**: `python build.py` crashes at its final `print` (the `→` character vs the cp1252 console) unless `PYTHONUTF8=1` is set. Set it (`$env:PYTHONUTF8=1` in PowerShell) or apply the fix in "Known issues".

## How to work here

- **Edit `src/` and `config.json`. Never edit `docs/` by hand** — it is generated and committed (it is what Cloudflare serves). After any change: `python build.py`, then commit `src/` **and** `docs/` together.
- Preview locally: `python build.py --serve` → http://localhost:8000
- Check before finishing: `python build.py` (read every `note:` / `todo:` line) and `python tools/qa_sweep.py` (needs `pip install playwright && playwright install chromium`). Today `qa_sweep` should only report the known-missing images on the Gates pages (see Open items); anything else is a regression.
- `python build.py --check-release` is **expected to fail** until the launch items are done. Don't "fix" it by weakening the checks.
- **Branches:** work on a branch for anything bigger than a typo. Merging to `main` deploys to production (the site is live), so check the branch preview first and merge only on Glancy's approval.
- You **cannot see Workers Build status** from here. After a merge, tell Glancy to check the `mayatuya` Worker → Deployments for the build on that commit.
- Local tools (pymupdf, playwright, Chromium) were installed outside the repo — don't add them as dependencies.

## Media and the 25 MiB rule (read before touching images or PDFs)

- `media_src/` holds originals and is **not in git**. The build **wipes `docs/` and re-copies only the files pages reference, from `media_src/`**. If a file is missing there, the build **silently removes it from `docs/assets`** and the next deploy breaks that image. Before committing any build, open `media_needed.txt`: there must be **no new `MISSING` lines** compared with the known list below.
- **Cloudflare rejects any single asset over 25 MiB.** The three paid PDFs were compressed to fit (the Spanish guide 170 MiB → 20.8 MiB). **The compressed versions are the canonical ones.** If `media_src/` still holds the originals, a rebuild will overwrite the compressed copies and the deploy will fail. Keep the compressed PDFs in `media_src/` (replace the originals) and keep the originals elsewhere, outside the repo.
- `python tools/fetch_media.py` downloads referenced files from the old WordPress site. It cannot fetch files that 404 there.
- Image spec for new photos: 1200×800, ~80% JPG, under 200 KB.
- Paid PDFs (`Guide-Campeche-First-Edition-ipt3rn.pdf`, `ES_Campeche_FirstEdition-zs7f1m.pdf`, `Tu-Negocio-Mejor-9m0ieq.pdf`) are protected **only by obscure filenames and noindex pages**. Never link them from indexable pages or list them in a sitemap. Revisit only if abuse appears.

## Voice and content rules (from the Codex)

1. **Brand voice:** calm, restrained, observational, human. Never salesy. Written as a founder — personal and lived, not corporate. **Never** use urgency language, hype, growth theatrics, "blogger-y" or algorithm-driven copy, marketing metaphors or exaggerated claims. Never position Maya Tuya as a mass-tourism platform, listicle brand, travel agency or influencer project.
2. **Destination content is first person** ("I came to Campeche expecting…"). This is intentional and locked.
3. **Bilingual pairs move together.** Every EN page has an ES counterpart (`pair`). Change one → change the other. **Never literal translation** — preserve meaning, rhythm and intent. Spanish is Mexican usage and equally respected. Aliado-facing content is **Spanish-first**.
4. **The Conscious Traveler is a tool/compass, never a "guide"** in copy. It is always free.
5. **Aliado benefit copy is vague and evocative** on every page — never state the specific benefit. **Aliado Fundador is never advertised on the website** (in-person only); Hazte Aliado mentions two tiers only, with no pricing.
6. **Contact email is `hola@mayatuya.com` for all audiences.** Phone/WhatsApp: +52 938 184 2944.
7. **Design tokens:** dark green `#013220` (primary; the theme palette also has `#0b3d2e`), gold `#c89e4b`, gold-dark `#9a7828`, cream `#f3eee2` (page background — **not** `#f2e9d0`), ink `#0c0b09`, muted `#5a5040`. Fonts: Playfair Display SC / Playfair Display (headings), Lato (body/labels), Cormorant Garamond (italic/pull). No new fonts or colours.
8. Don't put a background colour on a page's widget wrapper div; section backgrounds go on the `<section class="mt-sec">` (dark green sections do this).
9. **No frameworks, no build tooling beyond `build.py`.** Zero dependencies (`lxml` is only for the legacy extractor). Links are root-relative (`/assets/…`, `/inicio/…`) and internal page URLs end with `/`.

## Forms and payments

- **Forms** post to Web3Forms. The email is the record. Subjects are tagged for Gmail filters: `[MT booking] <experience> (EN|ES)`, `[MT acuerdo] <tier> (ES)`, `[MT traveler]`, `[MT contact]`, `[MT hazte-aliado]`. **Do not rename form field names** (`first_name`, `guests`, `preferred_date`, `acuerdo_accepted`, `tier`, …) without telling Glancy — they appear in the notification emails. A honeypot field (`botcheck`) is built in.
- After a successful submit: Conscious Traveler forms → the download page; acuerdo forms → the matching `/bienvenido-aliado…` page; Hazte Aliado → `/inicio/aliado-en-proceso/`; contact/booking show an inline confirmation.
- **Acuerdo flow:** Step 1 pay (Destacado/Fundador via Stripe link; free Aliado has no payment) → Step 2 accept via the form → welcome page.
- **Stripe:** Payment Links only, referenced as `{{stripe:key}}` tokens resolved from `config.json`. Keys: `destacado_monthly`, `destacado_annual`, `fundador`, `guide_campeche`, `contribution`. Never invent a link. The three existing live links are stored under `stripe_live_reference` for when Glancy is ready. **Stripe post-payment redirect URLs to set at launch:** Tu Negocio → `/tu-negocio-mejor/`, Campeche guide → `/campeche-guide-download/`.
- Payment-link URLs and the Web3Forms access key are public by design. **Never commit secret keys or API tokens.**
- Mailchimp: the old FluentForm tagging is retired. Contacts are added manually from form emails (Gmail labels) until an integration is justified by revenue.

## Hosting, staging and live

- Cloudflare account Worker name: **`mayatuya`** (must match `name` in `wrangler.jsonc`). Canonical host: **https://mayatuya.com** (apex). `new.mayatuya.com` and the `*.workers.dev` URLs still serve the same build but `worker.js` marks them `X-Robots-Tag: noindex`. Repo is connected to Workers Builds (Cloudflare GitHub app authorised); pushes to `main` build and deploy.
- `config.json`: `"hosting": "cloudflare"`, `"mode": "live"` (set at go-live, Nov 2026). Live mode: indexable pages are `index, follow`; pages flagged `noindex` in `pages.json` (acuerdo, bienvenido, download, legal, aliado-en-proceso) stay `noindex, follow` and out of the sitemap; canonicals, `sitemap.xml` and `robots.txt` use the apex. `"mode": "staging"` still exists as a switch (every page noindex, `new.` canonicals, Disallow, no sitemap).
- `worker.js` (in front of the static assets, `run_worker_first`): 301s `www.mayatuya.com` → apex, and adds noindex on any non-apex host. It only sees `www` traffic once `www` is attached to the Worker in Cloudflare (a DNS/custom-domain change — Glancy's call).
- Cloudflare facts: `_redirects` / `_headers` are read from `docs/`; real 301s for old WordPress URLs. `/about` → `/about/` is a **307** (Cloudflare's trailing-slash handling) — acceptable.
- Old WordPress sitemaps (`/wp-sitemap.xml`, `/wp-sitemap-*`) 301 to `/sitemap.xml` (generated in live mode).
- **Never, without Glancy's explicit go-ahead:** point `www` at the Worker; add, change or delete any DNS record; merge risky changes straight to `main`; disable or delete anything in Cloudflare or GitHub. In particular never touch **MX, SPF/DKIM/TXT, autodiscover, apex or www records** — email depends on them.

## Known issues to fix (small, safe — fix on a branch)

1. **Windows console:** `build.py` should not crash on `→`. Add `sys.stdout.reconfigure(encoding="utf-8")` near the top (guard with `hasattr`).
2. **Media safety net:** before wiping `docs/`, index the existing `docs/assets/img` and `docs/assets/dl` and use them as a **fallback source** when a referenced file isn't in `media_src/`. A build must never delete a deployed image. Keep the `MISSING` report.
3. **Size check:** `build.py` warns above 50 MB (GitHub's limit). Cloudflare's limit is **25 MiB per file** — change the check to fail on > 25 MiB.
4. Favicon / fonts / flags: Google Fonts and `flagcdn.com` flag images are external; self-hosting is a later optimisation.
